SECTION 01

INTRODUCTION

The Urban Last-Mile Logistics Crisis & Computational Formulation

01 / Introduction

The Urban Last-Mile Logistics Crisis

📦 1. Exploding Demand

India's e-commerce and quick-commerce explosion has inundated logistics networks with millions of daily parcels. Customer satisfaction hinges entirely on delivery punctuality.

💸 2. The 53% Cost Trap

Industry logistics studies confirm that the last-mile leg accounts for over 53% of total delivery expenses. Suboptimal packing and erratic routing cause fuel waste, overtime, and severe SLA chargebacks.

🛣️ 3. Hyderabad Scope

From Main Parcel Warehouse (Begumpet) to high-density commercial hubs (Hitec City, Gachibowli) out to long-distance highway corridors (Woxsen University on NH65).

🎯 Academic Project Mission & Vision

SmartRoute demonstrates how foundational Data Structures and Algorithms—such as Binary Min-Heaps, Adjacency Lists, 0/1 Dynamic Programming memoization, and greedy heuristics—cooperate to turn chaotic urban parcel dispatching into a mathematically optimal, 100% on-time reality.

01 / Problem Statement

The Multi-Constrained Dispatch Challenge

🛑 Physical & Operational Invariants
  • Payload Capacity Bound: Vehicle capacity limit $C = 75\text{ kg}$. Overloading is illegal; underloading sacrifices margin.
  • Hard SLA Time Windows: Each parcel has deadline $d_i$ (180 to 380 mins). A single late arrival triggers financial chargebacks.
  • Non-Euclidean Road Network: Straight-line Euclidean distance fails in urban traffic and highway flyovers.
  • Precedence Invariant: Pickup must strictly occur before Drop ($\text{Pickup}_i \prec \text{Drop}_i$).
  • 0/1 Discrete Indivisibility: Parcels cannot be split into fractional pieces.
🧩 Intractability & Combinatorial Complexity
Capacitated Vehicle Routing Problem with Time Windows (CVRPTW)

Stop Permutations for n = 20 stops:
20! ≈ 2,432,902,008,176,640,000 combinations.
Brute-force evaluation = Millions of compute years.

Because full CVRPTW is strongly NP-hard, our engineering breakthrough is a Two-Tier Algorithmic Decomposition that guarantees global optimal profit and 100% on-time feasibility in polynomial time (under 15 ms).

SECTION 02

LITERATURE REVIEW

Classical Algorithmic Benchmarks & The Identified Research Gap

02 / Literature Review

Algorithmic Foundations & Literature Survey

1. Classical Heuristics
Clarke & Wright (1964)

Pioneered route merging by distance savings. However, classical heuristics prioritize mileage reduction alone, entirely ignoring heterogeneous parcel profit margins and hard customer delivery deadlines.

2. Shortest Path Search
Edsger Dijkstra (1959)

Non-negative edge relaxation with Binary Min-Heap Priority Queue runs in $O((V+E)\log V)$. Solves point-to-point routing, but does not solve combinatorial parcel packing.

3. 0/1 Knapsack DP
Bellman (1957); Martello & Toth

Pseudo-polynomial $O(n \cdot C)$ memoization table guarantees global maximum profit. However, classic knapsack assumes static capacity, ignoring road networks and spatial transit times.

🔍 Identified Research Gap Addressed by SmartRoute

Existing literature separates parcel selection (Knapsack) from vehicle routing (TSP/Dijkstra). SmartRoute introduces a coupled Two-Tier Pipeline with iterative feasibility repair: selecting provably optimal parcels via 0/1 DP, routed along Dijkstra shortest paths, and dynamically pruning bottleneck stops if deadlines are threatened.

02 / Methodology

Urban Graph & Dijkstra Min-Heap Priority Queue

📍 Hyderabad Metropolitan Road Network

We model Greater Hyderabad as an undirected, non-negatively weighted graph $G = (V, E)$ centered on Main Parcel Warehouse (Begumpet).

  • Vertices ($|V| = 22$): Key hubs including Ameerpet, Hitec City, Gachibowli, Secunderabad, Miyapur, Sangareddy, and Woxsen University.
  • Edges ($|E| = 34$): Real arterial roads and NH65 corridor with true distance weights.
  • Data Structure: Adjacency List (`Map`) ensuring $O(V + E)$ spatial footprint over dense matrices.
⚡ Binary Min-Heap Priority Queue
// Edge Relaxation Condition
if dist[u] + weight(u, v) < dist[v]:
    dist[v] = dist[u] + weight(u, v)
    parent[v] = u
    minHeap.push((dist[v], v)) // O(log V)

Traditional array search takes $O(V^2)$ because finding minimum unvisited node requires $O(V)$ scans. Our Binary Min-Heap Priority Queue achieves instant $O(1)$ root extraction and $O(\log V)$ sift-ups, cutting total runtime to $O((V + E)\log V)$.

02 / Methodology

0/1 Knapsack Dynamic Programming Formulation

📐 Bellman Recurrence Formulation

Let $DP[i][c]$ denote maximum profit achievable considering first $i$ parcel requests with capacity $c \in [0, C]$:

DP[i][c] = max( DP[i-1][c], DP[i-1][c - w_i] + p_i )
  • Choice 0 (SKIP): Exclude parcel $i \implies DP[i-1][c]$
  • Choice 1 (TAKE): If $w_i \le c$, load parcel $i \implies p_i + DP[i-1][c - w_i]$
  • Boundary Base Case: $DP[0][c] = 0$ for all $c \in [0, C]$.
🔍 Backtracking Recovery & Greedy Limitations
// Backtracking from DP[n][C]
for i = n down to 1:
  if DP[i][w] != DP[i-1][w]:
    selected.push(item[i-1])
    w -= item[i-1].weight

Why Greedy Fails: Sorting by profit density ($p_i / w_i$) is mathematically optimal only for continuous fractional items. For discrete packages, greedy packing leaves unusable payload gaps, missing high-value shipments.

02 / Methodology

Route Invariants & SLA Feasibility Repair

1. Precedence Invariant

• Invariant: $\text{Pickup}_i \prec \text{Drop}_i$.

• State Sets: Maintains `pickedUp` and `delivered` hash sets.

• Gating: A drop action is strictly locked from the candidate action queue until its physical pickup has occurred.

2. Payload Safety Invariant

• Invariant: $0 \le \text{load}_s \le C$ at every stop.

• Dynamic Telematics: Starts at 0 kg at Depot. At pickup: $\text{load} += w_i$. At drop: $\text{load} -= w_i$.

• Overweight stops are pruned before route commitment.

3. SLA Feasibility Repair

• Invariant: $t_{\text{arr}} \le d_i$.

• Bottleneck Pruning: If a delivery arrives late, scheduler identifies the lowest-margin offender and defers it.

• Guarantees 100% on-time delivery on the final manifest.

03 / Viva Defense

Faculty Viva Q&A: Technical Defense Strategies

Q1: Why not pure DP for full VRP?

Answer: Exact multi-stop VRP with Time Windows requires tracking the visited subset in DP state (Held-Karp). This incurs exponential $O(n^2 \cdot 2^n)$ states and factorial permutations $O(n!)$. For 35 orders, $2^{35} \approx 34\text{ billion}$ states. Decoupling into 0/1 Knapsack DP ($O(n \cdot C)$) followed by Dijkstra spatial heuristic executes in under 15 ms.

Q2: Why use a Binary Min-Heap?

Answer: Without a Min-Heap, finding the next unvisited vertex requires an $O(V)$ linear scan, giving $O(V^2)$ total runtime. A Binary Min-Heap provides $O(1)$ root lookup and $O(\log V)$ key updates, reducing complexity to $O((V+E)\log V)$—critical for responsiveness on urban road networks.

Q3: When does Greedy match DP?

Answer: Greedy is provably optimal for Fractional Knapsack (continuous items). In discrete 0/1 Knapsack, Greedy is optimal only when parcel weights divide capacity evenly with identical profit densities. For discrete parcels, Greedy leaves unusable capacity fragments.

Q4: How enforce Pickup-Before-Drop?

Answer: The scheduler maintains `pickedUp` and `delivered` hash sets. A drop action is strictly locked until its package ID exists in `pickedUp`. Furthermore, cumulative vehicle load invariants ($0 \le \text{load} \le C$) are validated at every hop.
